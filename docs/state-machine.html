The state machine, and how the call hangs itself up

Six states, five events, five tools. The backend is the only authority: it owns the transition table and rejects any tool call that is not legal for the state the session is actually in. The browser renders what the server says and relays the session config the server issues — it never decides a transition.

Which tools are callable where

Gating lives in TOOL_STATES, not in ad-hoc checks at each call site. No tool lists a closing state, which is what makes those states terminal: every tool call after an escalation, a lock, a reschedule or a finalized intake is refused. A refusal still returns the authoritative record, so a rejected call resyncs the UI instead of desyncing it.

Tool Callable from Leads to Notes
verify_identity verification intake On a match. Three failed attempts instead lock the session.
request_reschedule verification reschedule The patient asked to be called back another time.
update_intake intake intake Writes known fields only; unknown keys are dropped.
flag_emergency intake alert The model's own escalation path, alongside the scanner's.
finalize_intake intake finalized Writes the summary and closes the record.

Hanging up

Reaching a closing state is not the same as being able to close the connection: the assistant still has a goodbye — or a 911 instruction — to say, and tearing down the peer connection cuts it off mid-sentence. The call waits for the model to finish speaking, then drops.

Invariants worth keeping

  • The server decides, the browser reports. Every response carries the authoritative record; the client adopts it as the single source of truth for state and UI, including on a refused call.
  • Instructions travel one stage at a time. The browser holds the data channel, so it must relay session configs — but it only ever gets the one attached to a transition the server just authorized.
  • Terminal means terminal for tools only. A closing state is closed to the agent, not to an emergency. The scanner keeps running on every patient turn.
  • Ending the call is a UI state, not a state-machine state. ending and ended describe the WebRTC connection. The conversation state stays whatever the server last said it was.
